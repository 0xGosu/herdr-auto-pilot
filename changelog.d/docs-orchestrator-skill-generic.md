- The `hap-orchestrator` skill is now repo-agnostic. `SKILL.md` holds only the orchestration loop, the standing rules and the command crib; everything tied to one forge, language or agent CLI moved into sub-files it references, so a herd on any codebase can take the skill unchanged and add only the siblings that match its stack. `reviewing-prs.md` split into `reviewing-work.md` (checking an agent's claims, flake versus regression, the scope of a delegation) and a new `github.md` (`gh` review comments, CI, merging, issues), and a new `machine-resources.md` covers the box agents share.
- Three standing rules the skill was missing, each of which an orchestrator broke in a single session. **It orchestrates, it does not implement** — no editing code, running builds or running test suites itself; that work goes to an agent, while reading diffs, logs and screens stays encouraged because that is how it verifies. **The event stream is the signal** — agent state changes, escalations, task movements and config changes all arrive on `hap stream orchestrator`, so polling `hap agents`, `herdr agent wait` or a bash loop over agent status is now explicitly forbidden rather than merely discouraged; a Monitor is justified only for something outside hap, such as a forge's CI. **Agents belong in an autonomous mode** — a default or manual mode stops at every edit approval, so the orchestrator checks the mode column and raises it with `hap mode <agent> acceptEdits --yes` before handing out work.
- Recorded what a session of orchestrating actually cost: `pgrep -f` matches the waiting shell's own command line, so a wait loop counts itself and never clears; a toolchain build can hardcode its own job count and ignore every control you set, so two agents building at once kill each other's work; background watchers are the first thing an out-of-memory kill takes, silently; and a prompt sent to a busy agent is queued rather than delivered, so a correction must supersede in its own words and be read back.
- Corrected guidance that was wrong: a repo whose test workflow runs on proposed changes only has no test build on its default branch, so "the merge commit's own build is the authority" pointed at an empty set. The skill now says to find out which builds run where before keying a watcher or a verdict on one.
